# Step 11 · 大模型基础直觉

> 目标：能用人话解释 4 个概念，**不需要**能手推公式。
> 验收：对着空气讲 3 分钟不打结。

## 要建立的 4 个直觉

### 1. 什么是 token？为什么计费按 token？

**一句话**：token 是模型处理文本的**最小单位**，不是字也不是词，介于两者之间。

```
"Hello world"     -> ["Hello", " world"]              = 2 tokens
"人工智能"         -> ["人工", "智能"]                  = 2 tokens（一般不按单字切）
"什么是RAG？"      -> ["什么是", "RA", "G", "？"]        = 4 tokens
```

- 英文约 4 字符 = 1 token；中文约 1-1.5 字 = 1 token
- **计费按 token**：因为模型的计算量正比于 token 数量（attention 是 O(n²)）
- **上下文长度限制**也按 token 算：模型能"看到"的 token 总数有上限

**为什么关心**：Prompt 写太长、历史对话全塞进去，token 消耗会指数级涨。这就是要"压缩历史""缓存"的原因。

> ⚠️ 本项目实测过：问免费模型"什么是 token"，它答成了"数字代币"——它把 AI 的 token 和加密货币的 token 混淆了。

### 2. 什么是 attention？为什么需要它？

**一句话**：attention 让模型在生成每个词时，**有选择地关注**输入里的其他词。

```
"小明把书给了小红，因为她明天要考试"
                              ↑ "她"指的是谁？
attention 会算出"她"和"小红"的关联度最高 -> 正确理解
```

- 没有 attention：模型只能顺序读，远距离的词关联不上
- 有 attention：任意两个位置可以直接建立关联（不管隔多远）
- **代价**：每对位置都要算，所以是 O(n²)——这是上下文长度受限的根本原因

**面试常问**："attention 的计算复杂度是多少？" → O(n²)，n 是序列长度。

### 3. 为什么有上下文长度限制？

因为 attention 是 O(n²)：

| 上下文长度 | attention 计算量（相对） |
|---|---|
| 1K tokens | 1 |
| 4K tokens | 16 |
| 32K tokens | 1024 |
| 128K tokens | 16384 |

翻 4 倍长度 = 计算量翻 16 倍。所以：
- 显存/速度撑不住更长的
- 即使撑得住，成本也高（按 token 计费）
- 而且有"lost in the middle"现象：上下文太长时，中间的内容模型容易忽略

**实践启示**：
- RAG 检索回来的内容不能无限塞，要 top-k 控制
- 长对话要压缩历史，不能全丢进去

### 4. 什么是 embedding？为什么能表示语义？

**一句话**：embedding 把文本变成一串数字（向量），**语义相近的文本，向量距离也近**。

```
"猫"   -> [0.2, 0.8, 0.1, ...]   (比如 1024 维)
"喵星人" -> [0.21, 0.79, 0.12, ...]  <- 和"猫"很近
"汽车" -> [0.9, 0.1, 0.3, ...]       <- 和"猫"很远
```

**为什么能表示语义**：模型训练时，经常出现在相似上下文的词，会被训练成相似的向量。
"猫"和"喵星人"总出现在相似的句子里 -> 学到的向量就很接近。

**这就是 RAG 检索的基础**：
1. 把知识库文档都转成向量存起来
2. 用户提问也转成向量
3. 算余弦相似度，找最接近的文档 → 那就是最相关的知识

**关键点**：
- 向量相似 ≠ 答案正确，只是"内容相关"
- 所以要 Rerank 重排序（更精确的相关性判断）
- 换 embedding 模型必须重建索引（向量空间不同了）

## 面试高频问答

| 问题 | 答题要点 |
|---|---|
| token 是什么 | 文本最小单位，计费和上下文长度都按它算 |
| attention 计算复杂度 | O(n²)，n 是序列长度 |
| 为什么上下文有限制 | O(n²) 计算量 + 显存 + 成本 + 中间内容易丢失 |
| embedding 为什么能表示语义 | 训练时相似上下文 -> 相似向量 |
| 向量检索的原理 | 余弦相似度找最近邻 |
| Transformer 和 RNN 的区别 | 可并行、任意距离直接关联；RNN 必须顺序处理 |
