# 模型幻觉实测记录

> 记录日期：2026-10-19
> 模型：智谱 `glm-4-flash`（免费）
> 用途：作为「免费小模型不可直接生产」的实证素材，面试可讲。

## 实测现象

用它回答 5 个 AI 领域基础概念，**4 个回答错误**，且每次回答都不一样。

| 提问 | 模型实际回答 | 正确答案 | 判定 |
|---|---|---|---|
| 什么是 RAG？ | "检索-评估-生成（Retrieval-Assessment-Generation）" | Retrieval-Augmented Generation，**检索增强生成** | ❌ 错 |
| 什么是 Function Calling？ | "函数调用是执行函数中的代码块" | 让 LLM 以结构化方式调用外部工具/函数的机制 | ❌ 错 |
| 什么是 MCP 协议？ | "用于微控制器的编程协议" | Model Context Protocol（模型上下文协议） | ❌ 错 |
| LangGraph 和 LangChain 什么关系？ | "LangGraph 是 LangChain 的数据基础" | LangGraph 是 LangChain 生态中的状态机式 Agent 框架（反向） | ❌ 错 |
| 向量数据库是做什么的？ | "存储和管理向量数据的数据库" | 基本正确 | ✅ 对 |

### 反复调用会得到不同错误

同一问题「用一句话解释什么是 RAG」调用两次，得到两个不同的错误答案：

- 第 1 次：`RAG代表"阅读、理解、生成"`
- 第 2 次：`RAG是"检索-摘要-生成"的缩写`
- 第 3 次：`RAG是检索-评估-生成（Retrieval-Assessment-Generation）`

**三次三个答案，且全部错误。** 这是典型的幻觉（hallucination）：模型在不知道答案时，会编造**看起来专业**但完全错误的解释，语气还很自信。

## 从这个现象能得出什么

### 1. 为什么必须做 RAG

模型的知识里**没有**这些新概念（MCP 是 2024 年底才提出的），参数化记忆里是空的。
RAG 的价值就是：**把外部知识检索出来塞进上下文**，让模型基于事实回答，而不是靠记忆瞎编。

→ 这正好解释了手册 Step 17「要求模型只基于检索内容回答，没检索到就说不知道」的必要性。

### 2. 为什么必须做评估（Eval）

如果只看"模型能流畅回答"，你会以为它答对了。**必须用评估集量化**才知道准确率。
→ 对应手册 Step 19：没有评估的项目，准确率全靠感觉。

### 3. 免费小模型 vs 主力模型

- 免费模型（glm-4-flash）：适合跑通流程、测试代码逻辑，**不适合生成需要正确性的内容**
- 主力模型（DeepSeek / 更大参数）：知识准确性和推理能力显著更强
- **学习阶段用免费模型没问题，但做 RAG 项目的"生成"环节要换更可靠的模型**

### 4. 面试怎么用这个素材

被问到「模型幻觉怎么缓解」时，可以这样答：

> 我在学习阶段实测过：用免费小模型问 RAG、Function Calling、MCP 这些概念，4 个问题错了 4 个，
> 同一个问题问三次得到三个不同的错误答案，而且语气都非常自信。
> 这让我直观理解了为什么生产环境要做这几件事：
> ① **RAG**——用外部知识约束，而不是靠参数记忆；
> ② **提示词约束**——要求"只基于给定材料回答，不知道就说不知道"；
> ③ **评估集**——量化准确率，否则幻觉你根本发现不了；
> ④ **模型选型**——关键路径不能图便宜用最小模型。
